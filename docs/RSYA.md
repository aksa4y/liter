# Подключение Яндекс РСЯ

Компонент `app/components/AdSlot.vue` подготовлен для реальных рекламных блоков вашего кабинета Яндекса.
В поставке ID пустые: реальные объявления не показываются. Включение слотов в коде не означает, что сайт уже принят в РСЯ или получает доход.

## Порядок подключения

1. Разместите сайт на собственном домене, заполните `NUXT_PUBLIC_SITE_URL` и добавьте площадку в кабинете РСЯ.
2. После доступности размещения создайте адаптивный баннерный блок для широких мест и отдельный блок для рекламного места в статье.
3. Возьмите **ID блоков из кода, который выдаёт ваш кабинет**. Не используйте примерные или чужие идентификаторы.
4. Укажите значения в `.env` для разработки/статической генерации или в переменных окружения хостинга для SSR:

```dotenv
NUXT_PUBLIC_YANDEX_RTB_BANNER_ID=ваш_ID_баннерного_блока
NUXT_PUBLIC_YANDEX_RTB_ARTICLE_ID=ваш_ID_блока_статьи
NUXT_PUBLIC_ADS_PREVIEW=false
```

Это подписи для замены, а не готовые рабочие ID. `.env.example` содержит пустые поля, чтобы не отправлять запросы с вымышленными значениями.

5. Перезапустите сервер разработки; для SSG выполните `npm run generate` и загрузите новую `.output/public`.
   В режиме SSR, после `npm run build`, задайте переменные в окружении процесса и перезапустите его.
6. Проверьте показ на собственном домене в кабинете и браузере, включая мобильный экран и переходы между страницами.

## Как работает компонент

- Скрипт `https://yandex.ru/ads/system/context.js` подключается один раз на страницу, только если задан ID.
- Рендеринг вызовом `Ya.Context.AdvManager.render({ blockId, renderTo })` ставится в очередь `window.yaContextCb`.
- Скрипт и блок загружаются при приближении места к экрану (IntersectionObserver, запас 250 px).
- Каждый экземпляр получает собственный контейнер. При навигации отложенный вызов уже закрытой страницы не выполняется.
- Повторяющихся таймеров и автоматического обновления объявлений нет.
- Высота контейнера зарезервирована, чтобы уменьшить сдвиг контента. При заблокированной рекламе остальной сайт продолжает работать.
- Компонент выводит подпись «Реклама». Финальный формат, размеры и настройки самого объявления задаются в кабинете Яндекса.

## Расположение

| Место | Переменная |
| --- | --- |
| После шрифтов на главной | `NUXT_PUBLIC_YANDEX_RTB_BANNER_ID` |
| После каталога | `NUXT_PUBLIC_YANDEX_RTB_BANNER_ID` |
| Подборки и шрифтовые пары | `NUXT_PUBLIC_YANDEX_RTB_BANNER_ID` |
| Страница шрифта | `NUXT_PUBLIC_YANDEX_RTB_ARTICLE_ID` |
| Внутри статьи, после второго раздела | `NUXT_PUBLIC_YANDEX_RTB_ARTICLE_ID` |

Один шаблон места можно использовать на разных страницах; одновременно на каждой странице выводится один экземпляр этого места.
Для отдельной статистики по разделам можно добавить новые поля runtimeConfig и передавать нужный ID в компонент.

## Предпросмотр мест

`NUXT_PUBLIC_ADS_PREVIEW=true` показывает пустые подписанные прямоугольники, когда ID не задан.
Никакие объявления при этом не запрашиваются. Для обычного показа сайта оставьте `false`.

## Перед публичным запуском

Сверьте создаваемые блоки с кодом вашего кабинета. Визуальная подпись и заготовленный компонент не заменяют настроек рекламной площадки.
Страница `/privacy` описывает фактическое поведение проекта и автоматически меняет раздел о рекламе при заданных ID.
Управление рекламной площадкой и её статистика находятся в кабинете Яндекса.
